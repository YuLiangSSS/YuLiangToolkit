# 🎲 随机数生成器

> 按可调的**下限 / 上限 / 精确度**生成随机数。数值用任意精度十进制精确表示，
> 所以下限能填 `1e30`、精确度能填 `0.000000000000000001`，结果也不会出现
> `0.30000000000000004` 这种浮点尾巴 —— 生成出来是什么，显示和复制就是什么。

[← 工具一览](../../README.md) ｜ [文档索引](../README.md)

> **界面布局**：左边「范围与精确度」与「生成选项」之间可上下拖，左右「设置区 / 结果区」之间可左右拖；
> 拖完自动记住，双击某条缝只恢复这一处，全部恢复默认在 **主页设置 → 界面布局 → 恢复默认布局**。

## 能做什么

- **任意大的区间**：下限 / 上限都能写几百位，内部用 `BigInteger` 存，不会因为超过 `long` / `double` 就出错。
- **任意细的精确度**：`1`、`0.1`、`0.01`、`0.001`…一直细到 `1e-18` 都能用；也能点键盘上方的预设按钮快速填。
- **精确结果**：生成值一定是 `下限 + k × 精确度`，用十进制精确还原 ——
  `0.1` 不显示成 `0.10000000000000001`，`1.5` 不会带一串零。
- **可调个数**：想一次要一堆就调「生成个数」（1 ~ 100，配置里最多 10000）。
- **去重 / 排序**：可以要求不重复抽样，也可以让结果按数值从小到大排（不是按字符串排序，`2` 排在 `10` 前面）。
- **分隔符**：换行 / 逗号 / 空格 / 制表，选完「复制结果」直接是想要的样子。

## 怎么用

1. 填**下限**和**上限**（含这两个数本身）。
2. 填**精确度**：这就是精度 —— `1` 只出整数，`0.1` 出到一位小数，`0.01` 出到两位小数。
3. 需要的话调「生成个数」、勾「允许重复 / 排序」、选分隔符。
4. 点「生成随机数」或按 **Enter**；结果出现在右边，点「复制结果」拿走。

## 精确度的意思（重要）

「精确度」= **步长**，生成值一定是下限加上若干个步长：

| 下限 | 上限 | 精确度 | 能生成的值 |
| --- | --- | --- | --- |
| 0 | 1 | 0.1 | 0, 0.1, 0.2 … 1（11 个可能值） |
| 0 | 100 | 1 | 0 ~ 100 的整数（101 个可能值） |
| -5 | 5 | 0.5 | -5, -4.5 … 5（21 个可能值） |
| 0 | 1 | 0.3 | 0, 0.3, 0.6, 0.9（上限对齐到 0.9） |

- **上限不在网格上时自动向下对齐**：保证结果**绝不超上限**，界面上会用蓝字提示对齐到了哪里。
- 区间比步长还小时只剩一个可能值（就是下限），这是正常的。
- 精确度必须大于 0；为 0 或负数会直接提示，不会生成。

## 设置项

改一下就自动存进 `Config\random-number\config.json`，没有保存按钮。

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 下限 | 0 | 含；可写负数、大整数、`1e30` 这类科学计数法 |
| 上限 | 100 | 含；不在网格上会自动对齐（结果不越界） |
| 精确度 | 1 | 步长，必须 > 0；决定结果的小数位数 |
| 生成个数 | 1 | 1 ~ 100（配置文件里手动写最多 10000） |
| 允许重复 | 开 | 关掉改成不重复抽样（最多只能出网格点数那么多） |
| 排序 | 关 | 勾上按数值从小到大排列 |
| 分隔符 | 换行 | 换行 / 逗号 / 空格 / 制表 |

> 下限 / 上限 / 精确度在配置里都是**字符串**（`"lower": "0"`），不是数字 ——
> 这样超大数和超细步长在存盘 / 读取时不会被浮点化丢掉精度。

## 文件放在哪

- 配置：`Config\random-number\config.json`（相对 **exe 所在目录**，不是仓库根目录）。
- 数据：本工具不写 `Data\`、不写 `Cache\`；「重建配置」会把上面这些选项恢复默认。
- 区块大小：和别的工具页一样存在 `Config\layout.json`（键名前缀 `random-number.`）。

## 常见问题

| 现象 | 原因 / 怎么办 |
| --- | --- |
| 结果条数比「生成个数」少 | 勾了「允许重复」以外还可能是不重复模式凑不满网格；界面上会说明网格有多少个刻度 |
| 上限写 1 但结果最大只有 0.9 | 精确度是 0.3，网格对不齐上限，自动向下对齐了（蓝字会提示） |
| 提示「精确度必须大于 0」 | 精确度填了 0 或负数 |
| 提示「上限不能小于下限」 | 两个数写反了 |
| 想要几百位的大数 | 直接填，输入框没有长度限制；生成和显示都是精确值 |

## 自检

`random-number` 组（`tests/YuLiangToolkit.FrameworkSelfCheck/RandomNumberChecks.cs`）：
十进制步长网格（任意大边界 / 任意细步长 / 上限对齐 / 非法输入）、无偏抽样（注入确定性随机源断言边界、去重、
随机源退化时不死循环）、排序与分隔符拼接、精确数轮子 `ExactDecimal`（解析 / 四则 / 除尽判定 / 数值比较）、
配置默认值与夹取、配置 JSON 往返（大数按文本保存不被浮点化）。
**不创建窗口、不碰剪贴板、不写真实 Config。**

共享的精确数轮子在 `src/YuLiangToolkit.Core/Numbers/ExactDecimal.cs`（计算器的任意精度大数也用它），
改那边属于跨层改动，按 `docs/dev/verification.md` 走全量自检。

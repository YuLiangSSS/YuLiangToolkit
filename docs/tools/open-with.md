# 🗂️ 打开方式

> 把凉雨工具集登记进 Windows 右键 → **打开方式**：列表里会出现 **3 个入口** ——
> **按文件类型打开**（自动分流）、**以文本方式打开**、**以压缩包方式打开**。
> 任意文件右键都能选到本工具；PDF / 图片 / Word / Excel / PPT / 压缩包 / 音视频 / 文本会自动交给对应功能。
>
> **开关在 主页设置 → 打开方式关联**；只有 **Release 构建 / `publish.ps1` 发布版**能打开，Debug 构建固定关闭。
> 关掉开关不只是不登记：每次启动都会自动清理 Windows 记住的旧条目，设置里还有「清理打开方式关联」按钮。

> **界面布局**（每个区块之间都能拖）：左边「登记到系统」和右边「按文件类型打开」之间可左右拖；
> 主区域与底部运行日志之间可上下拖，拖完自动记住；双击某条缝只恢复这一处，
> 全部恢复默认在 **主页设置 → 界面布局 → 恢复默认布局**。

## 能做什么

| 入口 | 效果 |
| --- | --- |
| **凉雨工具集（按文件类型打开）** | 看扩展名自动分流：PDF → PDF 阅读器、图片 → 图片连续阅读器、`.docx` → Word 阅读器、`.xlsx` → Excel 阅读器、`.pptx` → PPT 阅读器、压缩包 → 压缩包工具、音视频 → 播放器、文本 / 代码 → 文本编辑器；**认不出的扩展名用文本编辑器兜底** |
| **凉雨工具集（以文本方式打开）** | 不管什么文件都交给**文本编辑器**（适合看日志 / 配置 / 脚本、或临时看陌生文件的内容） |
| **凉雨工具集（以压缩包方式打开）** | 不管什么文件都当成压缩包交给**压缩包工具**（探测格式、密码、内容列表；不是压缩包会在列表里标「读取失败」，不会破坏文件） |

> 三个入口用同一套单实例逻辑：程序已经开着时，选「打开方式」只是把文件交给现有窗口，**不会再多开一个窗口**。

## 怎么用

1. **用 Release 构建 / `publish.ps1` 发布出来的 exe** 启动（Debug 版这个开关是灰的，见下面「构建门禁」）。
2. 打开 **主页设置**（右上角 ⚙）→ 滚到「**打开方式关联**」→ 勾选
   「**在右键「打开方式」里显示凉雨工具集（3 个入口）**」。
   （左侧「文件」分类 → **🗂️ 打开方式** 这一页也能看当前状态、修复 / 清理，但开关统一在主页设置里，避免两处状态打架。）
3. 到资源管理器里右键任意文件 → **打开方式** → 选择需要的入口（首次可能等几秒才刷新列表）。
4. 想换默认程序：Windows 的「打开方式 → 始终使用此应用」仍然有效；也可以点页面上的
   「打开「默认应用」设置」在系统设置里选一次。

### 关闭 / 清理（Windows 会记住旧条目）

- **取消勾选**：立即清掉本工具写进注册表的打开方式入口和入口副本 exe，并把开关落盘成关闭。
- **每次启动自动清**：开关关着时，程序启动会检查一次；只要系统里还有**本功能**留下的痕迹
  （状态键 / 入口副本 exe / 我们自己的 Applications 条目），就自动清掉，不需要每次手动点清理。
  （如果从来没用过本开关，PDF / 图片阅读器自己的「文件关联」条目归那些阅读器的设置管，本功能不会擅自删。）
- **「清理打开方式关联」按钮**：立即执行同样的清理（Debug 版也能点），并把开关置为关闭。
- 清理只删「打开方式」相关条目：**不改任何后缀的默认程序 / 双击关联**（那属于 Windows「默认应用」和
  各阅读器自己的文件关联开关）；清完后资源管理器的列表可能要等几秒 / 重开对话框才刷新。

### 构建门禁（为什么 Debug 版不出现）

- 只有 **Release 构建**（`dotnet build -c Release`）或 **`publish.ps1` 发布版** 允许登记；
  Debug 构建里 `OpenWithRegistration.IsBuildSupported = false`，主页设置开关是灰的，启动时还会把残留清掉。
- 原因：Debug 版路径在 `bin\Debug\...`，开发时换目录 / 重建 / 删 bin 都会把系统里的「打开方式」变成坏入口；
  自检也会反复启动 Debug 版，不应该污染真实注册表。
- 想用这个功能：跑 `.\publish.ps1`，用 `dist\YuLiangToolkit\YuLiangTookit.exe`（或你自己的 Release 构建）打开本页面启用。

页面上的其它东西：

- **状态说明**：显示是否已登记、入口副本是否与当前程序版本一致（以及 Debug 构建的不可用原因）；
- **修复 / 刷新**：程序更新或把文件夹挪了位置后点一下，会按当前 exe 重建入口副本和注册表命令（Debug 下不可用）；
- **清理关联**：立即删掉系统里的打开方式条目 / 入口副本（Debug 也能用）；
- **列表里会出现的 3 个入口**：逐条说明三种模式（和上表一致）；
- **按文件类型打开（自动模式）**：右侧列出「哪个工具认领哪些扩展名」；
- **模拟**：填一个文件路径 → 显示自动模式会交给哪个工具（**只显示结果，不会真的打开文件**）。

## 数据与注册表

| 内容 | 位置 |
| --- | --- |
| 入口副本 exe | 和主程序 **同一个目录**：`<主程序名>.open-text.exe` / `<主程序名>.open-archive.exe`（只是同一个程序的两个入口名，依赖仍在主程序目录；「按文件类型」直接用主程序 exe） |
| 打开方式注册 | `HKCU\Software\Classes\Applications\<入口 exe 名>`（`FriendlyAppName` / `DefaultIcon` / `shell\open\command`） |
| PDF / 图片阅读器的打开方式引用 | `HKCU\Software\Classes\<后缀>\OpenWithProgids` 与 `Explorer\FileExts\<后缀>\OpenWithProgids` 里的 `YuLiangToolkit.PdfReader` / `YuLiangToolkit.PictureViewer`（打开或关闭本开关时都会清掉这些**打开方式引用**，避免列表里出现重复 / 旧路径条目；不删 ProgId、不改双击关联） |
| 本功能状态 | `HKCU\Software\YuLiangToolkit\OpenWith`（只记「已登记 + 主程序路径」；清理时整个删掉） |
| 开关配置 | `Config\shell\config.json` 的 `openWithAssociationEnabled`（主页设置里改，自动落盘） |
| 页面配置 | `Config\open-with\config.json`（只记「模拟」输入框上次的路径） |

> **只写当前用户（HKCU）**，不需要管理员权限；**不改任何后缀的默认程序**（`UserChoice` 由 Windows 保护，
> 也属于未公开行为，本工具不硬抢）。取消勾选 / 清理会删掉 3 个 Applications 条目、2 个入口副本，
> 以及 PDF / 图片阅读器登记的打开方式引用（双击关联仍然有效）。

## 常见问题

**Q：为什么列表里出现 4 个「凉雨工具集」？**
A：如果之前单独开过 **PDF 阅读器 / 图片阅读器设置里的「文件关联」**，那两个阅读器会额外登记打开方式条目
（`YuLiangToolkit.PdfReader` / `YuLiangToolkit.PictureViewer`）。本功能**在关闭 / 清理自己登记时会把它们也一起清掉**，
所以正常情况下看不到；如果你从没开过本开关、只开过阅读器的关联，那些条目归阅读器设置管。
阅读器的双击关联/默认程序不受影响。

**Q：不是有开关吗，为什么还要「清理」按钮？**
A：Windows 会把「打开方式」的选择 / 旧登记记在注册表里（Applications、OpenWithProgids 等），
光把开关改成关闭不一定能立刻让它从列表消失。所以本功能做了两层保障：
① 关闭开关 / 点「清理」时立即删干净；② 开关关着时**每次启动**再自动检查清理一次。

**Q：关掉开关后，某个后缀（例如 .png）的「打开方式」里还看得到本工具？**
A：如果那个后缀的**默认程序**已经被设成了本工具的图片 / PDF 阅读器（阅读器自己设置里的「文件关联」），
Windows 会把「默认程序」也列在打开方式里 —— 这是系统行为，本开关**不会去改默认程序**（否则双击行为会变）。
本功能自己的 3 个入口会全部消失；想连那一条也去掉，去对应阅读器的设置里关掉文件关联，或在 Windows
「默认应用」里换一个默认程序。

**Q：为什么「以文本方式 / 以压缩包方式」要用入口副本，而不是一个程序写三个注册表项？**
A：Windows 的「打开方式」列表**按 exe 路径去重**：同一个 exe 即使写三条不同参数的命令，也只会显示成一条。
所以用两个同目录的入口副本（复制主程序 exe，体积和主程序相同、依赖共用）来区分路径；
点哪条入口就带 `--open-as=text` / `--open-as=archive` 启动，主程序据此选模式。

**Q：为什么以文本方式打开后，自动保存不工作了？**
A：这是**故意的保护**：文本编辑器默认 0.9 秒自动保存，而「打开方式」可能把 `.exe` / `.zip` 这类二进制
交给它；如果误触键盘就自动写回去，可能**直接写坏原文件**。所以从「打开方式」打开的标签会**暂停自动保存**
（Ctrl+S / 保存按钮仍然可用；关掉该标签重新从编辑器打开即恢复正常自动保存）。

**Q：程序更新 / 换目录了怎么办？**
A：开关开着时启动会自动按当前路径刷新入口副本和命令；也可以到「打开方式」页点「**修复 / 刷新**」，
或在主页设置里关掉再打开一次。

**Q：想彻底恢复原状？**
A：主页设置里取消勾选，或点「清理打开方式关联」；`HKCU\Software\YuLiangToolkit\OpenWith` 会一起删掉。
之后 Windows 的「打开方式」里不会再出现本软件（PDF / 图片阅读器如果单独开了关联，双击行为仍在，
但它们的打开方式引用也会被本功能的清理清掉）。

## 自检

`open-with` 组只测纯逻辑（三种模式 / 命令行解析 / 扩展名分流 / 注册表命令拼装 / 状态只读函数 /
构建门禁 / 清理痕迹检测），**绝不调用登记 / 取消登记**（避免往开发机真实注册表写东西；
Debug 构建的 `Register` 在碰注册表之前就被门禁拒绝，自检只断言这个拒绝行为）。真正的登记往返由用户点界面或发布前手动验证。

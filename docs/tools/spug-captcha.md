# 📨 Spug 验证码测试

> 联调 [Spug 推送助手](https://push.spug.cc) 的**短信 / 邮箱验证码模板**：粘贴控制台复制的推送 URL、
> 填手机号或邮箱，点「发送验证码」；收到后把 6 位验证码填到底部点「验证」，
> 工具在本地比对并告诉你成功还是失败。

[← 工具一览](../../README.md) ｜ [文档索引](../README.md)

> **界面布局**（v0.42.0 起每个区块之间都能拖）：缝隙悬停亮起蓝线 + ↔ / ↕ 光标（平时只留一条淡淡提示线）。
> 短信 / 邮箱两栏可左右拖，两栏 / 验证码验证、验证码验证 / 日志之间各有一条上下缝，拖完自动记住；
> 双击某条缝只恢复这一处；全部恢复默认在 **主页设置 → 界面布局 → 恢复默认布局**。

## 能做什么

- **左栏「短信验证码」**：填推送 URL（`https://push.spug.cc/sms/<模板编码>`）、11 位手机号、有效分钟数，
  点「发送验证码」—— 工具会先把验证码发给 Spug，再调接口显示最近一次发送状态。
- **右栏「邮箱验证码」**：填推送 URL（`https://push.spug.cc/mail/<模板编码>`）、邮箱、场景（scene）与有效分钟（minute），
  点「发送验证码」；流程和短信一样，只是发给邮箱。
- **验证码可以自定义，也可以留空随机**：两栏都有「验证码（可选）」输入框 ——
  留空时每次随机生成 6 位数字；想固定验证码（例如 `123456`）就填 4~6 位数字或字母，工具发出去的 `code` 就是它。
  这个输入框只存在本次运行内存里，不写进配置。
- **底部「验证码验证」**：把收到的验证码填进去点「验证」，工具在**本地比对**：成功显示绿色，失败显示红色；
  下面「发送 / 验证信息」是只读日志，接口返回、`request_id`、错误原因都记在这里。
- **验证是本地比对，不是服务端校验**：Spug **没有校验验证码的接口**，所以工具只能核对
  「你填的是不是刚才发出去的那串」，不代表真的能登录 / 注册。生产环境请把校验放服务端（见「安全提示」）。
- **兼容两种短信模板**：模板里是 `${code} ${number}`（code + number 两个参数）或只有 `${code}` 都行；
  邮箱的官方中文 / 英文模板靠**两个不同的模板 URL** 区分（英文一个 URL、中文一个 URL），没有语言参数。

## 怎么用

### 短信

1. 在 Spug 推送助手控制台选好短信验证码模板，把它的推送 URL（形如 `https://push.spug.cc/sms/<模板编码>`）
   复制到左栏「推送 URL」。**输入框里只放控制台复制的完整调用地址**，
   不要写 `${code}` / `${number}`（它们是 Spug 服务端的占位符）。
2. 填 11 位手机号。
3. 有效分钟数默认 5：模板里含 `${number}` 占位符时必填；只含 `${code}` 的模板可以留空（留空就不传 `number`）。
4. 「验证码（可选）」：留空则每次随机生成 6 位数字；想用固定验证码就填 4~6 位数字或字母（如 `123456`）。
5. 点「发送验证码」，看下面的「最近一次发送状态」；接口返回和错误原因在底部日志里。
6. 手机收到短信后，把其中的验证码填到底部「验证码验证」，点「验证」。

### 邮箱

1. 复制邮箱模板的推送 URL（形如 `https://push.spug.cc/mail/<模板编码>`）到右栏。
2. 填邮箱地址。
3. 场景 scene 默认「登录验证」，**最多 12 字，不能含链接 / 域名**；有效分钟 minute 默认 5。
4. 「验证码（可选）」：留空随机生成 6 位；也可以填 4~6 位数字或字母用自己的验证码。
5. 点「发送验证码」，看「最近一次发送状态」与底部日志。
6. 收到邮件后把验证码填到底部，点「验证」。

### 验证

1. 底部输入框填刚才收到的验证码。
2. 点「验证」——成功是绿色，失败是红色主题色；旁边还有一行**待验证提示**，
   告诉你当前有没有已经发出、等你填回来的验证码。
3. 想看这轮请求到底发生了什么，看下面的「发送 / 验证信息」日志。

## 它到底发了什么

> 排查时对照这里：工具只是按 Spug 的接口约定发请求，日志里是 Spug 原样返回的 JSON。

- **短信**：`GET <推送 URL>?to=<手机号>&code=<验证码>[&number=<有效分钟数>]`
  - 例：`GET https://push.spug.cc/sms/<模板编码>?to=13800000000&code=123456&number=5`
  - `number` 只在模板含 `${number}` 时才带；只用了 `${code}` 的模板不需要 `number`。
- **邮箱**：`POST <推送 URL>`，`Content-Type: application/json`，请求体（值都是字符串）：

  ```json
  {"to":"user@example.com","scene":"登录验证","code":"123456","minute":"5"}
  ```

- **成功判断**：Spug 的 HTTP 状态固定是 200，真正的业务码在响应 JSON 里 —— `code == 200` 才算成功。
  成功体带 `msg` 和 `request_id`（日志里能看到，找客服 / 查控制台发送记录时用得上）；
  失败体形如 `{"code":400,"msg":"..."}`，`msg` 就是「常见问题」里那些文案。
- **`code` 从哪来**：来自页面上的「验证码（可选）」—— 留空时工具随机生成 6 位数字，填了就用你填的 4~6 位数字 / 字母；
  日志里只显示「验证码：自定义 / 随机生成（不显示）」，不会打印验证码本身。
- `${code}` / `${number}` 是 **Spug 服务端的模板占位符**，由 Spug 发消息时替换 ——
  不要把占位符写进 URL 输入框；输入框只放控制台复制的完整调用地址（不含占位符）。

## 常见问题

| 日志 / 报错文案 | 原因 | 怎么办 |
| --- | --- | --- |
| `请使用to参数指定发送目标手机号` | 短信请求没带上 `to`：手机号没填，或 URL 不是控制台复制的完整地址 | 填好 11 位手机号；URL 只放 `https://push.spug.cc/sms/<模板编码>` 这种完整调用地址 |
| `to参数包含无效手机号` | 手机号不是 11 位，或带了空格、`+86`、横线 | 只填 11 位数字 |
| `to参数包含无效邮箱地址` | 邮箱格式不对（少了 `@` 或域名） | 检查邮箱拼写再发 |
| `模板编码错误，请核对并注意大小写，连续多次错误将触发IP限流` | 模板编码被改过 / 大小写不一致 / URL 贴错 | 回 Spug 控制台重新复制，别手敲；已经连错几次就停一会儿，等 IP 限流解除 |
| `无效的数据格式` | 推给 Spug 的内容不是它要的格式，常见是 URL 输入框里混进了 `${code}` 之类的占位符或多余字符 | URL 输入框只放完整调用地址，占位符交给 Spug 服务端 |
| `发送频率超限` | 点太快，被 Spug 侧限流 | 等一会儿再发，别连续点 |
| `未完成实名认证` | Spug 账号没完成实名认证 | 去 Spug 控制台完成实名认证 |
| `短信余额不足` | Spug 短信余额用完了 | 去 Spug 充值 |
| `邮件余额不足` | Spug 邮件余额用完了 | 去 Spug 充值 |
| `scene、code 或 minute 缺失` | 邮箱请求缺字段：scene 空着、minute 没填等 | 填好场景和有效分钟再发；code 由工具生成，反复出现就重新发送一次 |

## 安全提示

- **推送模板 URL 就是调用凭证**：谁拿到都能用它发消息、消耗你的额度。**不要**发到公开网页 / 聊天群 /
  代码仓库 / 客户端安装包里。
- 本工具把推送 URL **明文**保存在 `Config\spug-captcha\config.json`（exe 旁边）；截图、分享日志前记得遮挡。
- Spug 没有校验验证码的接口，本工具的「验证」只是**本地字符串比对**；**生产环境的验证码校验必须放服务端**，
  这个工具只适合个人联调。

## 注意

- 工具要能访问 `push.spug.cc`；发不出去时先看底部日志里的请求 / 网络错误。
- URL 输入框只放控制台复制的完整调用地址，不要写 `${code}` / `${number}`（Spug 服务端的占位符）。
- 短信模板含 `${number}` 时有效分钟数必填；只含 `${code}` 的模板可以留空。
- 「验证码（可选）」只在本次运行的内存里，**不写配置**；关掉工具 / 重启程序后清空（默认又是随机生成）。
- 邮箱的中文 / 英文模板是**两个不同的模板 URL**，没有语言参数 —— 要英文模板就贴英文模板的 URL。
- 发送 / 验证记录只在界面日志里，关掉工具就没了，不会存到 `Data\` 里。
- 连续快速点「发送验证码」容易触发 Spug 的频率限制 / IP 限流，测试时慢一点。

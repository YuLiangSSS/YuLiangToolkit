# ⭐ osu! 等级计算器

> 拖入一批 osu!mania 谱面（`.osu`），自动算出每张谱的**星数（Star Rating）**和**等级（Level）**，
> 表格里同时列出 OD / 键数 / 标题 / 难度名 / 艺术家 / 谱师。
> **只读谱面，不会修改或生成任何文件。**（从早先那个独立小工具「LevelCalculator」改写过来。）

> ⚠ **先说结论**：**等级（Level）只对 8K 谱面有参考意义** —— 公式是按凉雨自己的 8K 谱面拟合的，
> 其它键数没有标定；**星数（SR）是通用的** —— 社区说的「**xxy 标级 / xxy rating**」就是这套 SR。
> 工具自动算出的等级属于**机器标级**，可能不准，必要时需要**人工手动修正**。

> 主页上归在「**音游工具**」类别里：点类别卡片进类别页，顶部面包屑（`主页 › 音游工具 › osu! 等级计算器`）
> 可以点回上一级。同一个类别下还有 osu! 下图器 / Key 转换器 / LN 转换器。

## 能做什么

- **批量算 SR / Level**：一次拖入多个 `.osu` 或整个文件夹（递归查找），自动一行一张谱地算。
  **SR 是通用的；Level 只对 8K 谱面有参考意义**（详见下文「星数、等级与标级怎么来的」）。
- **表格查看**：Level、Star Rating、OD、键数、Title、Difficulty、Artist、Creator、状态。
  - 加载失败的谱面（非 mania / 文件损坏 / 键数不在 1~10）会**标红**并在状态列写明原因。
  - Level 算不出来（SR 为 0 / 超出公式范围）时显示 `-`，不是 `NaN`。
- **重新计算**：改过谱面的 OD / 内容之后，点「重新计算」把表格里所有行重新读一遍。
- 纯本地、不联网，也**不写任何文件**（没有输出目录）。

## 怎么用

1. 把 `.osu` 文件或文件夹拖进页面（或点「选择文件…」）；文件夹会**递归**找所有 `.osu`，
   重复文件自动去重。拖进来后**自动开始计算**，进度条显示 `已算 / 总数`。
2. 算完看表格：一行 = 一张谱面；鼠标悬停行能看到完整路径 / 失败原因。
   加载失败的谱面行是红底、状态列会写具体原因。
3. 中间可以点「取消」（当前这张算完就停）；算完后可以：
   - **重新计算**：改了谱面 OD / 内容后让全部行重算（左下 / 右下都有入口）；
   - **清空表格**：把列表清掉重新拖（不会删磁盘文件）；
   - **打开谱面文件夹**：选中行时打开它所在的文件夹；没选中时打开列表第一个文件所在目录。
4. 右上角「参数说明 ▾」展开算法说明与注意事项。

> 文件列表**不持久化**：关掉工具 / 切走页面就清空了。工具也不改谱面，随便点。

| 列 | 内容 |

## 星数、等级与标级怎么来的

- **星数（SR）**：用 `StarRating.cs` 的算法（**Star Rating Rebirth / `srcalc` 思路的 C# 重写**；其中
  `Utils.cs` 来自 ppy osu!lazer，MIT）。它**不是** osu! 客户端/官方 mania 难度算法 —— 实测同一张 4K 谱，
  两边星数相差约 1.2 星；谱面加载时算一次，读到 0 / NaN 时再兜底重算一次。
- **SR 就是通用的「xxy 标级 / xxy rating」**：社区常说的「xxy 标级 / xxy rating」用的就是这套 SR
  （同一套 Star Rating Rebirth 思路的重写，数值可能因实现 / 谱面文件版本略有出入）。
  它**和键数无关**：4K / 7K / 8K 都能算、也能直接横向比较 —— 想跨键数比难度，看 SR 就行。
- **等级（Level）**：由上面的 SR 再套一层经验换算公式（分段）：
  - 星数在 **2.76257856739498 ~ 10.5541834716376**：`Level = 6.9615 × e^(0.1374 × SR)`；
  - 更低的星数（> 0）：`Level = 3.6198 × SR`；
  - 更高的星数（< 12.3456789）：`Level = 2.791 × SR + 0.5436`；
  - 其它（SR ≤ 0、≥ 12.3456789、NaN）：**显示 `-`**。
- **等级是按凉雨自己的 8K 谱面拟合的，所以只适用 8K 谱面**：公式系数来自凉雨那套 8K 谱面
  （旧工具名就叫「8k Level Rating Tool」），没有做其它键数的标定。因此：
  - **8K 谱面**：Level 可以参考；
  - **其它键数**：工具仍会套公式给出一个 Level，但这个值**没有标定、没有参考意义**，
    别当成真实等级 —— 看 SR 即可。
- **机器标级可能不准**：工具自动算出来的 Level 属于「机器标级」（自动拟合估算），
  特殊谱面、拟合边界附近都可能与人工标级有出入；实际拿去标级时**可能需要人工手动修正**，
  工具数值只作参考，不替代人工判定。
- 公式是**作者（凉雨）拟合的经验值**，不是 osu! 官方数据；同一个 SR 在别处看到的
  “等级”可能不一样。边界处（2.7626 / 10.5542）有两段公式交接造成的微小跳变，属于既有行为。

## 注意

- **等级只对 8K 谱面有参考意义**：公式是按凉雨 8K 谱面拟合的，其它键数没有标定；4K / 7K 等
  请看 SR（通用的 xxy rating）。工具照样会算其它键数的 Level，但那个数字别当真实等级用。
- **机器标级可能不准**：自动算出的等级是拟合估算值，特殊谱面 / 拟合边界处可能需要**人工手动修正**。
- **只支持 osu!mania**（`.osu` 里 `Mode: 3`）且键数在 **1 ~ 10**；其它谱面会标红并给出原因
  （std / taiko 谱直接提示，不会误算成 mania 星数）。
- **星数不是 osu! 客户端显示的星数**：算法不同（Star Rating Rebirth 思路 vs 官方 mania 难度算法），
  实测可差 1 星以上；等级公式又是在这套 SR 上、按 8K 谱面拟合的，所以更不能当官方难度 / 官方等级。
  谱面文件的版本（v14 / 新版）与实现细节也会让数值略有浮动。
- **表的顺序就是拖入顺序**（同一文件夹内按文件名排序）；目前**不支持点列排序 / 删除单行 / 导出**。
- 计算是**串行**的（解析库的编解码内部有静态状态、非线程安全），几百张谱会慢一点；
  大批量时别同时开两个窗口算同一批文件。
- 计算过程在后台线程跑，不卡界面；但表格行很多时滚动 / 刷新仍会有一点开销。
